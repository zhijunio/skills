# PostgreSQL

Read this when a task configures PostgreSQL, chooses SQL types, or defines
database time-zone behavior. Schema migrations live in
[flyway.md](flyway.md), persistence mappings in [mybatis-plus.md](mybatis-plus.md),
and a local container in [docker.md](docker.md).

## When to use

- Configure a PostgreSQL datasource or JDBC driver
- Choose PostgreSQL column types or database time-zone behavior
- Diagnose PostgreSQL-specific application configuration

## When not to use

- Engine tuning, replication, or PostgreSQL operations →
  [postgresql-developer](../../postgresql-developer/SKILL.md)
- Schema migration structure → [flyway.md](flyway.md)
- Entity and Mapper conventions → [mybatis-plus.md](mybatis-plus.md)
- Local PostgreSQL container → [docker.md](docker.md)

## Rules

1. Use the PostgreSQL JDBC driver `org.postgresql:postgresql` with runtime
   scope. Use the Spring Boot BOM or the build tool's Spring Boot dependency
   management to select a compatible version. Do not add
   `spring-boot-starter-jdbc` when using MyBatis-Plus.
2. Use `timestamptz` for instants. PostgreSQL stores the instant and renders it
   in the session time zone; it does not retain the originally supplied zone.
   Use `timestamp without time zone` only for a wall-clock value whose zone is
   intentionally not part of the domain.
3. Keep application and database sessions in UTC. Set PostgreSQL's server or
   database default time zone to `UTC` for local environments and configure
   application connection/session settings accordingly when the environment
   does not inherit that default. Do not use a regional zone to represent an
   instant; convert to a user's zone at the presentation boundary.
4. Do not rely on the machine's local time zone for persisted values. Use
   `Instant` in Java for `timestamptz`; JSON timestamp serialization follows
   the skill's Core Rules.
5. Name tables in singular `snake_case` (`purchase_order`) and columns in
   `snake_case` (`created_at`). Column names describe the field without
   repeating the table name: use `status` in `purchase_order`, not
   `purchase_order_status`. Table names may be PostgreSQL reserved words; use
   double quotes for such identifiers consistently in migrations and queries.
   Prefer lowercase names so PostgreSQL's identifier folding stays predictable.
   Keep Java property names in camelCase and map exceptions explicitly when
   necessary.
6. Name indexes `idx_<table>_<columns>` and unique constraints
   `uq_<table>_<columns>`. Index columns used by frequent filters, joins, and
   ordering based on actual query patterns. Do not add an index to every
   column; primary keys and unique constraints already provide indexes.
7. Declare foreign keys for real ownership or referential-integrity rules,
   name them `fk_<table>_<referenced_table>`, and choose `ON DELETE` behavior
   deliberately. Add an index on the referencing columns when joins or parent
   deletes need it; PostgreSQL does not create that index automatically.
8. Use database defaults for stable, database-owned values such as boolean
   flags, counters, and optimistic-lock versions. Keep defaults aligned with
   nullability (`NOT NULL DEFAULT ...`). For audit timestamps, choose one
   source of truth: this skill's MyBatis-Plus convention fills them in Java;
   do not add a competing database timestamp default unless the application
   intentionally supports writes outside that path.
9. Treat database constraints as the final authority for concurrent writes.
   Do not implement uniqueness as `SELECT` followed by `INSERT`; two requests
   can both pass the read. Declare the unique constraint, let the write decide
   the winner, and translate the constraint failure into a stable application
   conflict response after the failed transaction has rolled back. Do not
   continue querying in a transaction after a database write has failed.
10. Keep transactions short and limited to database work. Do not hold a
    transaction open across email, HTTP, or other remote calls. If retry is
    safe for the operation, retry the complete unit in a fresh transaction;
    never retry only the failed statement inside an aborted transaction.
11. Test constraints, optimistic-lock conflicts, and concurrent write
    behavior against PostgreSQL Testcontainers, not H2 or mocks. Bound
    application concurrency against the database connection pool: virtual
    threads do not increase PostgreSQL capacity. See
    [testing.md](testing.md), [mybatis-plus.md](mybatis-plus.md), and
    [async.md](async.md).

Example migration fragment; it assumes an earlier migration creates
`customer(id)`:

```sql
CREATE TABLE purchase_order (
    id bigint GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    customer_id bigint NOT NULL,
    external_id text NOT NULL,
    version integer NOT NULL DEFAULT 0,
    status text NOT NULL DEFAULT 'PENDING',
    created_at timestamptz NOT NULL,
    updated_at timestamptz NOT NULL,
    CONSTRAINT fk_purchase_order_customer
        FOREIGN KEY (customer_id) REFERENCES customer (id),
    CONSTRAINT uq_purchase_order_external_id UNIQUE (external_id)
);

CREATE INDEX idx_purchase_order_customer_id ON purchase_order (customer_id);
```

Choose identity generation only when it matches the application's ID
strategy.

## Verify

The template's `"user"` table demonstrates explicit quoting of the reserved
identifier in its [entity](../assets/template-maven/src/main/java/com/example/templatemaven/user/persistence/UserEntity.java)
and [migration](../assets/template-maven/src/main/resources/db/migration/V1__create_user_account.sql).

`compose.yaml`, and SQL configuration; confirm the effective PostgreSQL
session time zone is UTC. Report any rule that cannot be verified from the
project configuration.
