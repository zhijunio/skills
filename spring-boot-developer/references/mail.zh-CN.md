# 邮件

邮件是出站集成，不属于数据库事务。将消息组装放在应用 Service 和精简的邮件适配器之后，使业务代码不依赖 SMTP 细节。

## 配置

使用 Spring Boot 管理的邮件 Starter，让 Boot 选择兼容的客户端版本。通过外部配置设置主机、端口、TLS 和凭据；不要提交生产凭据。邮件连接默认超时可能是无限值，应设置有限的连接、读取和写入超时：

```yaml
spring:
  mail:
    host: ${MAIL_HOST:localhost}
    port: ${MAIL_PORT:1025}
    properties:
      "[mail.smtp.connectiontimeout]": 5000
      "[mail.smtp.timeout]": 3000
      "[mail.smtp.writetimeout]": 5000
```

上面的本地值指向开发 SMTP 收件箱。部署环境应使用 TLS 和 Secret Store 中的凭据。除非 SMTP 可用性必须决定应用是否就绪，否则不要启用启动时连接检查。

## 消息边界

暴露 `sendOrderConfirmation(OrderId)` 这样的领域操作，不要让 Controller 任意传入发件人、收件人和正文。校验收件人地址，使用应用拥有的发件人身份，并确保模板对 HTML 内容进行转义。主题和正文不能直接接受不可信的邮件头输入；头部中的 CR/LF 可能导致注入。

文本、HTML 和附件使用 `JavaMailSender` / MIME 消息。大附件应存入文件存储；可行时提供受授权的下载链接。避免记录完整正文、附件、凭据或个人信息。

使用收件人预期的 Locale 渲染模板，并转义不可信 HTML。入队前校验附件数量和大小；大文件优先提供短时有效的授权下载链接。SMTP 接受消息只表示完成交接，不代表邮件已进入收件箱。可用时跟踪服务商的投递/退信事件，区分收件人永久失败和传输暂时失败，并抑制反复硬退信的地址。

## 事务时机与投递保证

不要在数据库事务中发送邮件。事务回滚无法撤回 SMTP 服务器已经接受的邮件。对于非关键通知，可发布应用事件并在提交后处理；异步投递可避免请求线程等待，但进程若在事务提交后退出，内存事件可能丢失。

对于重要业务邮件，应在业务变更所在的同一数据库事务中写入 Outbox 记录。后台 Worker 发送待处理消息并记录尝试次数和状态。为不确定的 SMTP 结果设计重试：服务器可能已经接受邮件，但客户端超时。使用稳定的消息/事件 ID、有界指数退避、最大尝试次数和运维可见的死信状态。SMTP 本身不保证恰好一次投递。

多个实例运行 Worker 时，应通过租约或行锁安全领取任务，并使重复发送可识别。监控最老待处理时长、尝试次数、永久失败和退信率；只看队列长度可能掩盖队列卡住。为邮件元数据定义保留期限；除非业务要求，不要保存完整正文。

参见[事务](transactions.zh-CN.md)、[消息](messaging.zh-CN.md)和[异步与定时任务](async-and-scheduling.zh-CN.md)。

## 本地开发与测试

使用 Mailpit 等本地 SMTP 收件箱，让开发者检查邮件而不向外部发送；参见[本地开发](local-development.zh-CN.md)。生产和本地使用相同邮件适配器，只改变配置。

无需真实 SMTP 即可测试消息构造和业务决策。使用本地邮件容器编写集成测试，验证 MIME 编码、模板渲染和实际投递交接。测试失败/重试状态，并确保事务回滚后不会发送通知。投递边界测试不能全部用 Mock 替代。

## 常见问题

- 在数据库事务提交前发送邮件——在提交后触发，或写入 Outbox。
- 用内存异步事件投递关键邮件——持久化发送意图，避免进程崩溃丢失。
- 将所有 SMTP 异常都视为明确未投递并无限重试——结果可能不确定；应幂等且有界地处理。
- SMTP 超时无限——设置连接、读取和写入超时。
- 记录邮件正文或密钥——记录消息 ID 和投递状态，不记录敏感内容。
- 使用用户提供的发件人或主题——发件身份由应用控制，并拒绝邮件头控制字符。
- 在本地开发或测试中发送真实邮件——使用本地收件箱和隔离配置。
