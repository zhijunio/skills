# 文件上传与下载

将上传文件视为不可信输入，将存储文件视为受保护资源。Spring MVC 负责 multipart HTTP 边界；存储适配器管理文件内容，Service 管理元数据、授权和生命周期。单实例演示可从本地磁盘开始；生产环境通常应使用对象存储或专用文件服务。

## 上传边界

在 Web 适配层接收 `MultipartFile`，校验后再传入 Service。不要将上传内容直接绑定到实体。设置单文件和整个请求的大小上限，并限制并发上传，防止临时文件耗尽内存或磁盘：

```yaml
spring:
  servlet:
    multipart:
      max-file-size: 10MB
      max-request-size: 12MB
```

校验文件大小、允许的媒体类型和文件签名。客户端提供的文件名和 `Content-Type` 都只是声明，并不能证明真实内容。若产品接受有风险的格式，应在允许下载前进行扫描。除非业务允许，否则拒绝空文件。

除单请求限制外，还要按主体/租户设置配额。解压前限制压缩包条目数、嵌套层数、解压后体积和压缩比；小文件也可能展开为耗尽磁盘的攻击。将 SVG、HTML、XML 和 Office 文档视为主动或复杂内容。文件完成校验/扫描前应隔离；除非经过安全净化，否则不要从已认证应用的同源地址提供不可信主动内容。

由服务端生成不透明存储键。原始文件名仅作为经过净化的展示元数据保存。不要将用户提交的文件名拼接到存储根路径，否则路径规范化错误会导致路径穿越或覆盖漏洞。文件应放在可执行程序的静态资源目录和 Web 根目录之外，并通过受授权的处理器下载。

## 元数据与存储边界

数据库保存文件元数据：不透明文件 ID、所有者或租户、存储键、大小、检测出的媒体类型、校验和、原始展示名、创建时间，以及按需保存的扫描状态。默认将大型二进制内容存入文件/对象存储。通过存储端口隔离本地文件系统和对象存储实现，便于替换。

数据库事务不能原子地提交文件系统或对象存储写入。应定义明确的生命周期：先将文件写入临时键，再保存元数据、提升对象，最后标记为可用；定时清理遗留临时对象。简单演示也可先写文件，再在元数据事务失败时补偿删除。清理操作应幂等且可观测。

## 下载边界

先用公开的不透明 ID 查找元数据，再检查当前主体是否有权访问该文件，最后从存储流式读取。不要公开存储路径，也不要允许调用方选择任意存储键。避免将大文件读入 `byte[]`；使用 `Resource` 或 `StreamingResponseBody`，并在已知时返回内容长度。

使用经过验证的媒体类型和安全编码的 `Content-Disposition` 文件名。对不可信或可执行格式优先使用 `attachment`，并发送 `X-Content-Type-Options: nosniff`。仅在客户端和存储实现确实需要时支持 Range 请求。未知 ID 返回 404，避免泄漏其他租户是否拥有某个文件。

若使用对象存储预签名 URL，签发前先授权，并将 URL 限定为单个对象、单种操作和较短有效期。预签名 URL 是 Bearer 能力：获得它的人在有效期内都能访问，之后应用层的授权检查也无法撤销它。保持 Bucket 私有，不要记录 URL。若需要立即撤销、逐次下载审计或应用强制限流，应由应用代理流式下载。

## 生命周期与测试

明确建模删除过程：删除元数据与文件，并允许重试清理；或将记录标为待删除，直到存储确认完成。只删除数据库记录不会删除对象，只删除对象则会留下失效元数据。

测试大小和类型拒绝、伪造签名、文件名路径穿越、授权失败、流式响应头和清理失败。存储测试使用临时目录或本地对象存储容器；数据库元数据测试使用生产同类型数据库。参见[持久化切片测试](testing-slices-persistence.zh-CN.md)和[Testcontainers](testcontainers.zh-CN.md)。

## 常见问题

- 信任上传文件名、扩展名或 MIME 请求头——校验内容并使用服务端生成的存储键。
- 将上传文件保存在 `static/` 或 `public/`——改为通过检查授权的处理器提供下载。
- 将无上限的上传内容读入内存——设置 multipart 限制，并对大文件进行流式处理。
- 只限制单次请求而不限制总量——按用户/租户设置存储和并发上传配额。
- 解压压缩包时不限制解压体积和条目数——限制解压资源并拒绝压缩炸弹。
- 从应用同源提供用户上传的 SVG 或 HTML——隔离/净化，或从独立源作为附件下载。
- 认为对象存储受 `@Transactional` 管理——定义暂存、补偿、清理或由 Outbox 驱动的生命周期。
- 只保护下载路由——针对每个文件 ID 检查所有者/租户访问权限。
- 未安全编码就把用户文件名放入 `Content-Disposition`——净化并编码展示文件名。
- 删除元数据后就认为文件已删除——协调存储清理并支持重试。
- 将预签名 URL 当作无害链接——它在过期前提供 Bearer 访问；应限制作用范围和有效期，且不要写入日志。
