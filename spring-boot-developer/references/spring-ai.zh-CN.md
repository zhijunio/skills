# Spring AI

本文梳理 Spring AI 应用的配置、ChatClient、会话、Prompt、结构化输出、RAG、流式响应、故障处理、成本、安全和测试。

## 配置

模型提供商凭据应从环境或秘密管理系统注入；不要提交 API Key。明确配置模型、超时、Token 上限和重试策略。模型名称及供应商价格会变化，应通过配置管理。

## ChatClient

使用 Spring AI 的 `ChatClient` 封装模型请求，让业务逻辑不依赖某个提供商 SDK。构造请求时明确系统提示、用户输入、上下文和输出格式；对失败和用量建立统一边界。

## 会话 ID

有状态对话必须显式定义会话身份和历史持久化策略。会话 ID 应由可信应用上下文管理，并执行用户 / 租户归属检查；不能让任意调用者读取其他会话历史。

## Prompt 模板

将 Prompt 模板与业务代码分开管理，明确区分系统指令、用户输入和检索上下文。用户内容必须视为不可信数据，不能允许其覆盖系统策略。避免将秘密或不必要的个人数据放入 Prompt。

## 结构化输出

需要机器处理时使用 DTO / Schema 约束输出，并对模型响应执行解析、校验和领域规则检查。模型生成的 JSON 仍是不可信输入；无法解析或不满足约束时应安全失败或重试，而非直接写数据库。

## RAG

检索增强生成需明确文档来源、切分、嵌入模型、向量存储和权限过滤。检索内容也可能包含恶意指令，应作为引用数据处理，而非系统指令。对每个用户和租户执行访问控制，避免跨用户检索泄漏。

## 流式响应

流式输出可降低首字延迟，但连接会保持更久。设置超时、取消传播、缓冲和客户端断开后的清理；不要把尚未完整校验的部分输出当成已确认结果。

## 故障处理

为模型调用设置连接和读取超时。只对短暂错误做有限重试，应用退避与抖动；不要盲目重试限流或不可幂等操作。定义提供商不可用时的降级体验。

## 成本与安全

限制输入 / 输出 Token、并发、速率和每用户费用；记录按操作、模型统计的 Token 用量与延迟。生产环境不要记录 Prompt 或完整响应；内容可能包含个人数据和内部资料。模型工具调用必须经过服务端授权，不可直接执行未经验证的模型输出。

## 测试

将业务逻辑与真实模型调用分离。使用 Stub 验证 Prompt 构造、解析、错误映射与降级；维护评估样例验证质量和安全回归。集成测试确认实际提供商配置和序列化行为，但 CI 不应依赖真实生产凭据或不受控费用。

## 使用 Spring Boot 3.5.x 时

Spring AI 的 API 受 Spring AI 版本影响。确认所选 Spring AI 版本适配当前 Boot / Spring Framework 版本，不能仅凭 Boot 版本推断 API。Advisor 接口等内容可能在 GA 前后变化。

## 常见问题

- 在代码中硬编码 API Key 或模型价格。
- 无 Token、超时、并发或费用上限。
- 把模型输出当可信命令或直接持久化。
- Prompt 记录到生产日志中。
- 忽略会话与租户的访问控制。
- RAG 检索没有权限过滤，或把文档内容当作可信指令。
- 对限流、超时或非幂等请求无限重试。
- 只用 Mock 验证技术流程，不评估质量、安全和回归。
